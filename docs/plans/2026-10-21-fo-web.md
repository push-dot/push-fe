**Goal:** Ship personal web (fo-mobile minus AI chat, usable as a job board) and employer web (verification, company, postings, applicants, employer AI chat, plans) inside `apps/fo-web`, while the two WebView detail pages keep working inside the mobile app.

## Decisions

These are the smallest choices the docs left open. Later tasks must follow them.

1. **Employer AI rides on `/conversations`.** `POST /conversations` body gains optional `audience: 'EMPLOYER'`, `postingId`, `applicationId`. List filter `audience=EMPLOYER`. Ultra PDF is `POST /conversations/{id}/attachments` (multipart `file`). The existing `conversations.create(title: string)` stays. New method: `conversations.createEmployer`. Company ownership is a server concern; the client only sends `audience`.
2. **Posting edit and close are not in api-spec 4.1, but feature-map 4.2 requires 수정 · 마감.** Add `postings.create`, `postings.update` (`PATCH /postings/{id}` with `expectedRevision`), `postings.close` (`POST /postings/{id}/close` with `expectedRevision`). Create body matches api-spec 4.1 plus `requirements`, `workConditions`, and `preferred`, because GET detail and the AI draft use those fields.
3. **`GET /sources` does not exist.** 내 서류 in real mode is the profile `resumeSourceId` plus ids uploaded in this browser session (same shortcut as fo-mobile). Mock mode answers `GET /sources`.
4. **Calendar read is additive.** `calendar.events(from, to)` calls existing `GET /calendar/events` (api-spec 3.12). Needed by 내 활동 › 캘린더. No Google connect UI.
5. **Routes** (browser). WebView router ignores everything except the two detail routes.

   | Path | Who |
   |---|---|
   | `/` | guest home |
   | `/jobs` | guest posting list |
   | `/search` | guest sees 공고 tab only |
   | `/postings/:id` | guest detail |
   | `/login` `/signup` | account type first |
   | `/auth/callback` | OAuth |
   | `/auth/verify` | email verify token |
   | `/auth/reset` | password reset confirm |
   | `/hub` `/profiles/:id` `/social` `/posts/:id` `/me` `/offers` `/offers/:id` `/notifications` `/settings` | login |
   | `/employer/verify` | employer, no company yet |
   | `/invites/:token` | employer accept |
   | `/employer/postings` `/employer/postings/new` `/employer/postings/:id/edit` | employer, verified |
   | `/employer/postings/:id/applicants` `/employer/postings/:id/applicants/:applicationId` | employer, verified |
   | `/employer/chat` `/employer/chat/:id` | employer, verified |
   | `/employer/members` | employer; invite/remove/transfer admin only |
   | `/employer/plans` | employer; checkout admin only |

6. **OAuth redirect** is `${origin}/auth/callback`, so dev is port 5174. api-spec's localhost example is 5173 (desktop). Send `redirectUri` as the page origin. Mock mode does not leave the page: the provider button stores a mock session.
7. **Return-to** is a same-origin path (`/` + no scheme, no `//`, no backslashes). Stored in `sessionStorage` key `push-return-to`. After login, `navigate` there once, then drop it. Default `/`.
8. **Session** lives in `localStorage` key `push-web-session` (`Session` JSON). WebView pages keep using `window.__PUSH__.token` and do not read this key.
9. **Design system.** `@push/design-system` palette is the desktop blue set, and its components pull Mantine and vanilla-extract. fo-web already has the mobile brand in `styles.css` (`#5B4CF0`, Pretendard). Do not mount Mantine. Reuse the existing CSS variables. Do not add `@push/design-system` as a runtime dependency.
10. **Locale control** calls `PATCH /me/settings` but the shell copy stays Korean. Full i18n is out of this pass.
11. **많이 찾는 검색어 / 최근 검색어.** Recent searches are `localStorage` `push-recent-searches` (max 8). Trending has no API (api-spec 6). Mock shows a fixed 1–8 list. Real mode hides the ranking.
12. **Home sections** use existing `PostingFilters.sort`: `latest`, `deadline` (마감 7일), `popular`. The client already documents that push-be ignores `sort` today; mock honors it.
13. **Fit on 지원활동** reads optional `fitScore?: number | null` on `Application`. Real mode shows the number only when the field is present. It is not a link. No part scores, no weakness, no "N점대".
14. **Share** uses `navigator.share({ url })` and falls back to copying the posting URL plus toast `링크를 복사했어요`.
15. **Employer social author.** `Post.author` gains optional `employer?: boolean` and `companyName?: string | null`. When `employer` is true, the UI shows `companyName` plus a `기업` badge and hides the person's `displayName`.
16. **`notifyApplicationStage` is optional** on `Settings` so fo-mobile's required object literal still typechecks. The web settings screen shows the fifth switch and sends the field.
17. **`BillingStatus.plan` stays** `'FREE' | 'PRO' | 'ULTRA' | null`. `audience` and `source` are optional. `checkout` accepts `'BASIC' | 'PRO' | 'ULTRA'` (old `'PRO' | 'ULTRA'` callers still compile). Employer plan reads use `billing.companyStatus()`, not a wider `BillingStatus.plan`.
18. **Seat limit display** uses `GET /companies/me` `seats.used` and `seats.limit`. Client also knows the table for copy when the payload is missing: no plan or BASIC → 0, PRO → 2, ULTRA → 5. Limit 0 copy: `Basic에서는 담당자를 초대할 수 없어요`. Over the limit: disable new invites, keep remove.
19. **Stage buttons** map only these four: 서류 통과 → `SCREENING`, 면접 → `INTERVIEW`, 합격 → `OFFER`, 불합격 → `REJECTED`. Terminal `REJECTED` (and `ACCEPTED` / `WITHDRAWN`) disables further changes. `stageBadge` in api-client already maps the read badges; do not change those strings.
20. **Chat plan gates (UI + API):** 공고 생성 and 서류 검토 (Push 지원자) on every employer plan including none? Spec: verification gates 공고 등록 and 기업 AI entirely. After verification, Basic includes 공고 생성 and 서류 검토. 면접 준비 requires PRO or ULTRA (`PLAN_REQUIRED`, `details.requiredPlan = 'PRO'`). External PDF requires ULTRA (`requiredPlan = 'ULTRA'`). No plan yet (verified, `plan: null`) is treated like Basic for AI features and like limit 0 for seats. Checkout is how they buy Basic.
21. **Employer without verification** can use the personal-shaped shell (browse, social, hub offers) but 내 공고, 공고 등록, and 기업 AI route to `/employer/verify`.
22. **No hub profile editor for employers.** `/me` for employers is 회사 정보, link to 담당자, link to 요금제, and 내 활동 chips 북마크 · 팔로우 · 게시글 only.
23. **Reference consent** checkbox copy, exact: `내 서류와 평가 결과를 가공해 다른 사용자와 기업의 AI가 참고 자료로 써요`. Signup sends `consentReference`. Settings can toggle `PUT /me/consents` later on the account card; include the switch on 설정 for a logged-in user.
24. **Mock personas** (query `as`): default personal guest until login. `?mock=1&as=personal` logs in as 김서준. `as=employer` is verified admin on Basic. `as=employer-pro` is Pro. `as=employer-new` is employer with no company. Document the URLs in the final report.
25. **fo-web reads `billing.companyStatus()` and `me.webNotifications()`** because widening `BillingStatus.plan` and `NotificationType` breaks fo-mobile exhaustive switches. Personal `billing.status()` and `me.notifications()` stay as they were. `CompanyBillingStatus.plan` is `'BASIC' | 'PRO' | 'ULTRA' | null`. `WebNotification` adds `APPLICATION_STAGE` and `target.kind: 'activity'`.
26. **Offer status labels.** Received SENT is `새 제안`. Sent SENT is `읽지 않음`. READ is `읽음`. ACCEPTED is `수락함`. DECLINED is `거절함`. AI_DONE notifications with a conversation target mark read and do not navigate.
